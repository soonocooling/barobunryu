# Claude Code 사용 기록 — dissect · parse · dashboard (원영)

> 대화를 내보낸 뒤 핵심만 줄인 정리본입니다. 키, 실명, 실제 금액, 계정 정보는 넣지 않았고
> 예시 금액과 가맹점은 모두 가짜 값입니다.

## 작업 방식
- 저장소의 `CLAUDE.md`와 `tasks/<파트>.md`가 절차를 정해 두었습니다. 저는 "해부 정리해", "파싱 개발 시작해"처럼 한 줄로 시작했고, Claude Code가 해당 `tasks` 파일을 끝까지 읽고 수행했습니다.
- 내 파트 소유 파일만 수정하고, 다른 파트 파일이나 팀장 소유 파일(`plan.md`, `collab-plan.md`)은 고치지 않고 PR 설명에 제안으로 남겼습니다.
- 커밋 전 `python -m pytest -q`, PR은 `main`으로, `main`에는 직접 push하지 않았습니다.

## 1. dissect — 원본 해부 정리
| 내가 한 요청 | Claude Code가 한 일 | 결과 |
|---|---|---|
| "해부 정리해" | `tasks/dissect.md`를 읽고 선행 조건 확인. 캡처와 알림 샘플이 없는 것을 확인하고 **지어내지 않은 채** 보고 | 사람이 해야 할 일(HUMAN_TODO 8번) 안내 |
| 하나은행 알림 텍스트 제공, "다른 은행도 처리되게 하고 싶다" | 알림을 샘플로 만들고 금액, 이름, 가맹점을 가짜 값으로 바꿈. 은행별 차이(금액 표기, 공백, 날짜 형식)를 읽기 규칙 표로 정리 | `docs/push-samples.md`, `tests/fixtures/push_samples.json` |
| 가리지 않은 캡처 업로드 | 규칙대로 **즉시 멈추고** 실제 금액과 이름이 보인다고 알림. 커밋 제외 | "원본은 올리되 유출은 막고 싶다" → 원본 전용 폴더를 `.gitignore`로 제외하고 샘플은 가짜 값으로 옮기는 방식으로 합의 |
| "정산은 토스가 아니라 카카오페이 기능이야" | 해부 문서의 전제를 고치고 체크리스트에 "토스에는 정산 기능 없음"으로 반영 | 사용자가 AI의 잘못된 전제를 바로잡은 사례 |
| 카카오뱅크 푸시, 카카오페이 알림톡 캡처 | 형식 차이(카카오뱅크는 제목에 금액, 본문에 `A → B`, 시각 없음)를 문서화. 정산과 취소는 현재 계약으로 표현할 수 없어 `expected: null`로 둠 | 샘플 9건 |

핵심 판단
- 캡처로 확인하지 못한 항목은 "확인 불가"로 적고 사실처럼 쓰지 않았습니다. 예: 같은 상대에게 카테고리를 바꾸면 다음에도 적용되는지, 엔빵 대표결제를 전액 지출로 잡는지.
- 카테고리별 합계가 지출 합계와 맞는지 **검산**해서 "카카오페이 출금은 `그 외`로 합산된다"를 추정했습니다. 단정하지 않고 추정이라고 표시했습니다.
- 발표 문장이 캡처로 다 뒷받침되지 않는 것을 팀장에게 알리도록 PR에 적었습니다.

## 2. parse — 입력·답장·알림 파싱
- 요청: "파싱 개발 시작해" → `tasks/parse.md` 절차대로 `parse_manual`, `parse_answer`, `parse_push` 구현과 `tests/test_parse.py` 작성.
- `parse_push`는 은행마다 다른 형식(하나은행 한 줄, 카카오뱅크 제목 + 화살표, 카카오페이 알림톡)을 각각 읽고, 정산과 취소는 `None`을 돌려주게 했습니다.
- **테스트가 잡은 버그**: "엔빵 3", "3빵"이 카페·간식 카테고리로 분류됨("빵" 키워드 충돌). 엔빵 표현을 빼고 카테고리를 찾도록 수정.
- **환경 문제**: 이 PC에 Python이 없어 테스트를 못 돌림 → Claude Code가 `winget`으로 Python 3.12를 설치. Windows에는 시간대 데이터(`tzdata`)가 없어 테스트 수집이 실패하는 것을 찾아 팀장에게 `requirements-dev.txt` 수정을 제안.
- 다른 팀원이 `main`에 먼저 올린 `parse_manual`과 충돌 → 지시대로 **양쪽 내용을 모두 남기는** 방식으로 병합. 병합 과정에서 `main` 코드의 버그 2건(위 "엔빵 3", 그리고 "내 몫 4명"의 4가 내 몫 금액으로 읽힘)을 최소 수정.
- 결과: 테스트 71건 → 병합 후 **132건 통과**.

## 3. dashboard — 비밀번호 보호 대시보드 1장
- 요청: "시작해" → `tasks/dashboard.md`에 따라 Next.js 앱 생성.
- 설치된 Next.js가 **16 버전**이라 `AGENTS.md`의 안내대로 설치된 문서를 먼저 읽고, `middleware`가 `proxy`로 바뀐 것과 `cacheComponents`가 `force-dynamic`과 함께 쓸 수 없는 것을 확인해 설정을 맞춤.
- 서비스 키는 `import "server-only"`와 서버에서만 호출하는 구조로 두고, 빌드된 브라우저 번들에서 키 문자열을 검색해 **노출이 없음을 확인**. 비밀번호 없으면 401, 비밀번호 미설정이면 전부 401.
- **실제 연결 문제 진단**: 화면에 "데이터를 불러오지 못했어요"가 뜸 → 키를 읽지 않고도 원인을 찾도록 서버 로그에 오류 코드만 남기게 수정 → `ENOTFOUND`(주소 오류)로 확인 → 사용자가 URL을 고쳐 해결.
- 사용자가 직접 한 일: Supabase 키 입력(채팅에 올리지 않고 `.env.local`에만), 브라우저 확인.

## 4. 협업·보안 관련
- Claude Code 권한 설정이 **비밀 키 파일 읽기**와 **리뷰 없는 PR 머지**를 막았고, 우회하지 않고 사용자에게 알렸습니다. 사용자가 직접 머지하거나 명시적으로 지시한 PR만 처리했습니다.
- GitHub CLI(`gh`)를 설치하고 사용자가 브라우저로 로그인한 뒤 PR 상태와 충돌을 직접 확인.
- PR 6개(#8~#13)가 머지됨. 문서 PR은 팀장 소유 파일을 최소 범위(해당 섹션, 한 줄)만 수정.
- 공개 저장소에 올라가는 파일이라 대화 기록도 키, 실명, 금액을 지운 뒤 올림. 이 파일이 그 결과입니다.

## 이 과정에서 배운 점
1. AI가 모르는 것을 **"확인 불가"로 남기게** 하면 문서의 신뢰도가 올라간다.
2. 테스트를 먼저 쓰면 합칠 때 생기는 버그를 바로 잡는다.
3. 개인정보와 키는 "AI가 안 읽게" 설계하는 것이 "나중에 지우는 것"보다 안전하다.
