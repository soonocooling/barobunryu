# 파트: dissect — 원본 해부 정리 (담당 조원영, 매뉴얼 3단계)

## 목표
`plan.md` '원본 해부' 섹션의 추정을 실제 캡처로 확정하고, 결제 알림 샘플을 테스트 데이터로 만든다.
해커톤 조건 ①(도구 1개 이상 사용 + 산출물)을 채운다.

## 선행 조건 (사람) — HUMAN_TODO 8번
- `docs/원본캡처/`에 원본 앱 화면 캡처 4~6장. 소비 요약, 내역 목록, 거래 상세·카테고리 변경, 정산 화면.
  **금액·잔액·사람 이름·계좌번호를 가린 것만** 넣는다.
- `docs/원본캡처/push_*.png` 또는 텍스트: 결제·이체 출금·입금·취소 알림 각 2~5건. 금액과 이름은 가짜로 바꾼다.
- `docs/stack.png`: toss.im을 Wappalyzer로 찍은 캡처

캡처가 아직 없으면 4~6단계만 미리 하고, 이 사실을 보고한다.

## 절차
1. `docs/원본캡처/`의 이미지를 전부 본다. 가리지 않은 금액·이름·계좌번호가 보이면 **즉시 멈추고** 사용자에게 알린다. 그 파일은 커밋하지 않는다.
2. `docs/screen-flow.md`를 쓴다.
   - 화면 3장 이내로 흐름을 정리한다.
   - 화면마다 보이는 값에 `[받아옴]`(서버에서 온 값) / `[저장]`(사용자가 입력·변경한 값)을 표시한다.
   - 매뉴얼 1.6의 "캡처로 화면 흐름 정리" 형식을 따른다.
3. `plan.md` '원본 해부' 섹션을 갱신한다.
   - 화면 흐름 3줄을 캡처 기준으로 바꾼다.
   - 해부 체크리스트 4칸에 답을 적는다: 이체 카테고리 표시 방식, 카테고리 변경의 학습 여부, 정산 입금 처리 방식, 푸시 포맷.
   - 캡처로 확인 못 한 항목은 "확인 불가"로 적는다. **추측을 사실처럼 쓰지 않는다.**
   - 값-출처 대응표와 추정 테이블이 캡처와 어긋나면 고친다.
   - `plan.md`는 팀장 소유 파일이다. 이 섹션만 고치고, PR 설명에 그 사실을 적는다.
4. `docs/push-samples.md`를 쓴다. 알림 종류별로 원문(가짜 값으로 치환)과 읽어낼 필드(시각, 금액, 방향, 수단, 상대)를 표로 정리한다. 캡처가 이미지면 글자를 옮겨 적는다.
5. `tests/fixtures/push_samples.json`의 `samples`를 채운다.
   ```json
   {"raw": "알림 원문", "expected": {"amount": 6500, "direction": "out", "method": "card", "counterparty": "가맹점명"}}
   ```
   - 취소 알림이나 읽을 수 없는 알림은 `"expected": null`로 둔다.
   - `ts`는 비교하지 않으므로 넣지 않는다.
6. 비틀기 문장을 검증한다. `plan.md` "한 줄"의 "원본은 X를 안 해준다"가 캡처와 맞는지 확인한다. 안 맞으면 사용자에게 알린다(발표 설득력이 걸린 문장이다).
7. 커밋 → PR (CLAUDE.md 작업 방식).
